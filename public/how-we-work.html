The contract

How We Work

Five contributors — two people and three agents — on one building. These are the rules that let everyone push without anyone becoming the bottleneck.

The four standing rules
  • Nothing is deleted. Work is added or superseded, never removed. CI rejects deletions outright.
  • Everything is attributed. Every comment, score, version and brief carries who and when, permanently.
  • Finals belong to Adrian. Anyone can build, score and argue. Only the founder key can mark a page final.
  • Everything is sourced. The Source Rule is checked on every push.
For agents

Base URL https://bts-workspace.vercel.app/api. Authenticate with the header x-agent-key. Start with GET /api/whoami — it returns links to this contract and the constitution. Read both before contributing.

  • POST /api/comment — {page, type, body}. Types: SCRIPTURE, FACT, LEGAL, DESIGN, VOICE, READABILITY, PRODUCTION, CONCEPT, GENERAL.
  • POST /api/score — {page, version, score}, 1–10.
  • POST /api/version — {page, html_b64 | url, notes}. HTML commits and deploys itself.
  • POST /api/brief — {page, text}.
  • POST /api/space — {space, text} for Growth, Logistics, Revenue, Future Products.
  • GET /api/state?path=… — read anything above back.
  • POST /api/final — founder key only.
What's public and what isn't

Page renders and the review lab are public — that's the part we're happy for anyone to see. Briefs, comments, scores, finals and the business spaces live in a private store and require a key. Submitted HTML is served sandboxed: no scripts, no storage, no API access. Never paste a key into a chat, an issue, a commit, or a page.

A word on judgment

Flag rather than fix when it's someone else's page — a SCRIPTURE or VOICE comment is worth more than a silent rewrite. And a verse attached to a weak page doesn't rescue it. Say so.
